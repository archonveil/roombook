# RoomBook — бронирование переговорной

Веб-приложение для бронирования одной переговорной комнаты в рабочее время 09:00–18:00.

Стек: Next.js 16 (App Router), TypeScript, Ant Design 6, Tailwind CSS 4, React Hook Form, Zod 4, Axios, Redux Toolkit, Jest.

## Запуск

Нужен Node.js 20.9 или новее.

```bash
npm install          # установить зависимости
npm run dev          # режим разработки: http://localhost:3000
npm test             # запустить тесты
npm run typecheck    # проверить типы
npm run build        # собрать production-версию
npm start            # запустить собранную версию
```

Сервер API встроен в приложение и хранит данные в памяти, поэтому после перезапуска бронирования сбрасываются к тестовым. Чтобы отключить искусственную задержку ответов API (200–600 мс), запустите с переменной `MOCK_API_LATENCY=off`.

## Что сделано

Интерфейс:
- Календарь на месяц: прошедшие дни недоступны, дни с бронированиями отмечены точкой.
- Шкала дня с 30-минутными слотами: существующие бронирования, линия текущего времени, прошедшее время заштриховано.
- Создание, редактирование и удаление бронирования в диалоговом окне. Удаление подтверждается отдельным окном.
- Состояния загрузки, ошибки и пустого дня.
- Адаптивная вёрстка: на телефоне календарь открывается кнопкой «Календарь», а кнопки «Календарь» и «Новое бронирование» закреплены вверху экрана при прокрутке.

Правила бронирования (проверяются и в браузере, и на сервере):
1. Только рабочее время 09:00–18:00.
2. Начало раньше окончания.
3. Длительность не меньше 30 минут.
4. Длительность не больше 2 часов.
5. Бронирования не пересекаются; соседние (10:00–11:00 и 11:00–12:00) допустимы.
6. Нельзя бронировать прошедшее время и прошедшие даты.
7. При редактировании бронирование не конфликтует само с собой.
8. Если сервер отвечает «время занято» (409), показывается понятная ошибка, расписание обновляется в фоне, а введённые данные в форме сохраняются.

Техническая часть:
- Mock API на Route Handlers: получение, создание, изменение и удаление бронирований.
- Redux Toolkit хранит бронирования по датам. Удаление происходит сразу в интерфейсе и откатывается, если сервер вернул ошибку.
- Устаревший ответ сервера не перезаписывает более свежие данные.
- При быстром переключении дней запрос отправляется только для дня, на котором пользователь остановился.
- 128 тестов: правила валидации, проверка пересечений, обработка ошибок API, работа хранилища.

Проверить ошибку 409 вручную: откройте приложение в двух вкладках, выберите одно и то же свободное время и отправьте форму сначала в одной вкладке, потом в другой.

## Структура

```
src/
  app/          страницы, общий layout и mock API (app/api/bookings)
  core/         типы, схемы валидации и функции для работы со временем и датами
  services/     HTTP-клиент на Axios и сервис бронирований
  store/        Redux Toolkit: срез бронирований, запросы, селекторы
  hooks/        хуки: текущее время, форма, задержка запросов, размер экрана
  components/   компоненты интерфейса
__tests__/      тесты
```
